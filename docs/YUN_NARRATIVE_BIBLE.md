# 《三盏灯熄灭之前》叙事与人物准则

这份文档用于维护云天明童话主线的连贯性、人物声音与选择质量。新增或改写文本时，以“先让玩家读懂一个完整童话，再让玩家发现技术隐喻”为第一原则。

## 1. 三则童话各自解决什么问题

### 第一则：画页之城

- 表层故事：一个渴望永远被记住的王国，请来画师绘制先王遗像，却因此把整座王国暴露给画页灾害。
- 推理顺序：永恒遗像 → 光与回声校准位置 → 三十九人失踪 → 迟到的钟声 → 黑伞实验 → 慢光黑域 → 已暴露后的撤离窗口。
- 核心主题：被记住不等于被所有人看见；黑域不是拦截武器的盾，而是以永久封闭换取的安全声明。

### 第二则：饥潮之海

- 表层故事：鹿暝从被饥潮封锁的港口寻找一条能让船离岸的路。
- 推理顺序：北陆货单 → 轻泡晶 → 小规模试验 → 弯曲船前航路 → 白色尾迹 → 造船与载重 → 夜航 → 不可公开的航路。
- 核心主题：技术可以救下一部分人，但船票、尾迹和被留下的人都属于方案本身，不能藏进附录。

### 第三则：深灯王子

- 表层故事：鹿暝在深海找到弟弟，并从他手中接过两条都不完美的生路。
- 推理顺序：沉钟岛 → 潜灯王子登场 → 王位与坐标 → 远航/慢灯 → 档案保存 → 社会代价 → 不完整的命令。
- 核心主题：方案必须保留失败记录、人的生活和未来修改权；技术答案不能替尚未出生的人完成伦理选择。

## 2. 技术隐喻的出场顺序

任何新技术概念必须依次出现：

1. **可感知的异常**：玩家先看见、听见或摸到现象。
2. **可复述的实验**：角色用童话世界里的物件验证规则。
3. **有限解释**：角色只解释当前证据支持的部分。
4. **人的代价**：床位、船票、失联、家庭、食物或名字受到什么影响。
5. **现实译码**：白塔最后才给出现代物理含义，并明确哪些仍是假说。

不要让角色在第一次看见道具时直接说出完整技术答案。

## 3. 人物声音

### 鹿暝

- 欲望：先弄清事实，再保证具体的人不被方案抹掉。
- 恐惧：自己会借“救王国”之名，重复王室把人写成数字的习惯。
- 语言：短问题、现场命令、名单和可执行动作；情绪上来时才说锋利的话。
- 避免：连续发表抽象格言；在没有证据时一次说出完整机制。

### 槐姨

- 欲望：让宏大方案落回饭、床、衣服、孩子与普通姓名。
- 恐惧：王室把牺牲包装成漂亮词语。
- 语言：宫廷旧事、生活细节、温和但损人的幽默；会打断不合时宜的争论。
- 避免：使用技术术语；像全知旁白一样解释宇宙。

### 风帆卫士

- 欲望：让船实际抵达，而不是让出航看起来像英雄故事。
- 恐惧：别人沿着他留下的错误航迹送死。
- 语言：短句、航海命令、载重、潮时、试航次数；只引用亲眼见过的事故。
- 避免：每句都以比喻或警句收尾。

### 折页匠

- 欲望：完成精确、永恒、没有背面的作品。
- 恐惧：误差、混乱与无法校准的目标。
- 语言：礼貌、精确、职业化；把残酷行为称为校光、丈量和工艺步骤。
- 避免：愤怒叫嚣、直接承认自己是恶人、解释猎手的全部战略。

### 空伞师

- 欲望：让后来者知道正确刻度，也知道刻度无法替居民同意。
- 恐惧：黑伞被当成无代价的护身符。
- 语言：计数、钟表、误差与操作限制；回答常从演示开始。
- 避免：只说“盾也是牢”而不给实验、时间或失败条件。

### 砾亲王

- 欲望：留住父亲、王位与可见秩序。
- 恐惧：父亲和王国像从未存在过。
- 语言：继承、仪式、公众评价；在情绪中暴露丧亲之痛。
- 避免：写成只会阻挠主角的愚蠢反派。

### 潜灯王子

- 欲望：保存选择所需的证据，而不是替未来发布命令。
- 恐惧：再次因为一份“完整命令”害死人。
- 语言：值班表、沉船记录、家族旧事；面对姐姐时会翻旧账、承认内疚。
- 避免：连续输出对仗哲理句；永远比其他人正确。

### 澄安与译码员

- 澄安关注停顿、原话、覆盖人数、署名责任和被行政模板删掉的人。
- 译码员关注分栏、证据等级、机制、失败条件与修订记录。
- 两人可以争论，但不能互相承担对方的职业口吻。

## 4. 选项写法

- 选项正文写玩家正在做什么，不写模糊态度，例如“记录尾迹数据”优于“谨慎一些”。
- 提示说明会获得什么线索、承担什么监察风险或进入什么报告方向。
- 同一节点的选择应在方法、价值或风险上形成真实差异。
- 关键因果节点不可被普通路线跳过；坏结局路线可以因主动删去信息而提前收束。
- 选择后的下一节点必须承接刚才的动作，不得凭空多出人物、材料或已完成的实验。

## 5. 段落自检

提交前逐项确认：

- 角色是否知道了自己不可能知道的信息？
- 道具是否在取得或介绍以前被使用？
- 这一段能否删掉一句“金句”而变得更像人说话？
- 技术解释之后是否立刻出现具体人的代价？
- 选项文本是否足以让玩家预测方向，而不是预测正确答案？
- 结局是否明确说明玩家提交了什么、谁得到保护、谁被留下以及哪里失败？

修改主线后运行：

```bash
npm run audit:narrative
npm run validate
```

叙事审计会检查不可达节点、重复对白、缺失选项提示、超长文本，以及第一则/第三则不可跳过的关键因果节点。
